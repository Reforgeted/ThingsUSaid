# 阶段 3：多实例配置与分组绑定 —— 详细设计文档

> **阶段定位**：实现小组件的"个性化"，让每个桌面小组件实例独立绑定一个分组。用户添加小组件时弹窗选择分组，桌面上可同时存在多个显示不同分组内容的小组件。  
> **前置依赖**：阶段 2 的 Glance 框架、数据刷新机制、widget_configs 表均已就绪。本阶段在此基础上扩展多实例配置能力。

---

## 1. 阶段目标与范围

| 模块 | 内容 | 说明 |
|------|------|------|
| **Configuration Activity** | 小组件配置页面 | 添加小组件时弹出，展示分组列表供用户选择 |
| **绑定持久化** | `widget_configs` 表 | 将 `appWidgetId` ↔ `categoryId` 写入数据库 |
| **Widget 数据读取** | 动态读取绑定关系 | `TodoGlanceWidget` 不再硬编码，而是根据实例 ID 查库 |
| **生命周期清理** | 删除小组件时清库 | 桌面移除小组件时，同步删除 `widget_configs` 记录 |
| **刷新策略优化** | 精确刷新 | 数据变更时，只刷新绑定了该分组的组件实例 |

## 2. 核心业务流程

### 2.1 添加小组件完整时序

```
[用户在桌面长按 → 添加小组件]
            │
            ▼
[系统启动 WidgetConfigActivity]
            │
            ▼
[Activity 加载分组列表（Compose UI）]
            │
            ▼
[用户点击「生活」分组]
            │
            ▼
[保存 WidgetConfig(appWidgetId=66, categoryId=生活ID) 到数据库]
            │
            ▼
[Activity setResult(RESULT_OK, intentWithAppWidgetId)]
            │
            ▼
[系统完成添加，触发 TodoGlanceWidget 首次渲染]
            │
            ▼
[TodoGlanceWidget 读取 widget_configs → 得知绑定「生活」→ 查 notes 表渲染]
```

### 2.2 小组件删除时序

```
[用户从桌面移除小组件]
            │
            ▼
[系统发送 APPWIDGET_DELETED 广播]
            │
            ▼
[TodoGlanceWidgetReceiver.onDeleted] ──> [删除 widget_configs 中对应记录]
```

## 3. Configuration Activity 详细设计

### 3.1 功能要求

- **启动时机**：用户从桌面小组件列表拖拽添加时，系统自动启动
- **界面**：全屏或 BottomSheet 风格，展示当前所有分组的列表（名称 + 色块）
- **用户操作**：点击某个分组即选中，保存配置并关闭
- **取消行为**：用户按返回键 → 返回 `RESULT_CANCELED`，系统取消添加小组件

### 3.2 Activity 代码结构

```kotlin
package com.example.thingsusaid.widget.config

class WidgetConfigActivity : ComponentActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 获取系统分配的 appWidgetId
        val appWidgetId = intent?.extras?.getInt(
            AppWidgetManager.EXTRA_APPWIDGET_ID,
            AppWidgetManager.INVALID_APPWIDGET_ID
        ) ?: AppWidgetManager.INVALID_APPWIDGET_ID
        
        if (appWidgetId == AppWidgetManager.INVALID_APPWIDGET_ID) {
            finish()
            return
        }
        
        setContent {
            ThingsUSaidTheme {
                WidgetConfigScreen(
                    appWidgetId = appWidgetId,
                    onCategorySelected = { categoryId ->
                        // 保存绑定关系
                        lifecycleScope.launch {
                            AppDatabase.getInstance(this@WidgetConfigActivity)
                                .appDao()
                                .saveWidgetConfig(
                                    WidgetConfig(
                                        appWidgetId = appWidgetId,
                                        boundCategoryId = categoryId
                                    )
                                )
                            
                            // 通知系统配置成功
                            val resultValue = Intent().putExtra(
                                AppWidgetManager.EXTRA_APPWIDGET_ID,
                                appWidgetId
                            )
                            setResult(RESULT_OK, resultValue)
                            finish()
                        }
                    }
                )
            }
        }
    }
}
```

### 3.3 UI 设计

```kotlin
@Composable
fun WidgetConfigScreen(
    appWidgetId: Int,
    onCategorySelected: (Long) -> Unit,
    viewModel: CategoryListViewModel = viewModel()
) {
    val categories by viewModel.categories.collectAsStateWithLifecycle()
    
    Scaffold(
        topBar = { TopAppBar(title = { Text("选择要显示的分组") }) }
    ) { padding ->
        LazyColumn(modifier = Modifier.padding(padding)) {
            items(categories) { category ->
                CategorySelectItem(
                    category = category,
                    onClick = { onCategorySelected(category.categoryId) }
                )
            }
        }
    }
}
```

## 4. GlanceWidget 改造：从固定到动态

### 4.1 核心变更

`TodoGlanceWidget` 需要从硬编码 `fixedCategoryId = 1` 改为：

1. 通过 `GlanceId` 获取 Android 原生的 `appWidgetId`
2. 查询 `widget_configs` 表获取绑定的 `categoryId`
3. 如果未找到配置（或配置的分组已被删除），显示"请点击配置分组"

```kotlin
class TodoGlanceWidget : GlanceAppWidget() {

    override suspend fun provideGlance(context: Context, id: GlanceId) {
        val appWidgetId = (id as? AppWidgetGlanceId)?.appWidgetId 
            ?: AppWidgetManager.INVALID_APPWIDGET_ID
        
        val config = AppDatabase.getInstance(context)
            .appDao()
            .getWidgetConfig(appWidgetId)
        
        val categoryId = config?.boundCategoryId
        val notes = if (categoryId != null) {
            AppDatabase.getInstance(context).appDao().getNotesByCategoryId(categoryId)
        } else {
            emptyList()
        }
        
        provideContent {
            WidgetContent(
                notes = notes,
                hasConfig = config != null,
                categoryName = config?.let { 
                    AppDatabase.getInstance(context).appDao().getCategoryById(it.boundCategoryId)?.name 
                }
            )
        }
    }
}
```

> **注意**：上述代码中通过 `Dao` 连续查询的方式在 `provideGlance` 中是可行的，因为这是一个 suspend 上下文。但为了代码整洁，实际实现时会封装到 `AppRepository` 中。

### 4.2 空状态处理

| 场景 | 显示内容 |
|------|---------|
| 用户刚添加，还未配置 | "请点击配置分组" |
| 已配置，但该分组下无便签 | "该分组暂无便签" |
| 已配置，分组已被用户删除 | "分组不存在，请长按重新配置" |

## 5. 生命周期管理

### 5.1 Receiver 扩展：监听删除事件

```kotlin
class TodoGlanceWidgetReceiver : GlanceAppWidgetReceiver() {
    override val glanceAppWidget: GlanceAppWidget = TodoGlanceWidget()

    override fun onDeleted(context: Context, appWidgetIds: IntArray) {
        super.onDeleted(context, appWidgetIds)
        // 清理数据库中对应的配置记录
        CoroutineScope(Dispatchers.IO).launch {
            val dao = AppDatabase.getInstance(context).appDao()
            appWidgetIds.forEach { id ->
                dao.deleteWidgetConfig(id)
            }
        }
    }
}
```

### 5.2 AndroidManifest 更新

Configuration Activity 需要在 Manifest 中注册：

```xml
<activity
    android:name=".widget.config.WidgetConfigActivity"
    android:exported="true"
    android:theme="@style/Theme.ThingsUSaid">
    <intent-filter>
        <action android:name="android.appwidget.action.APPWIDGET_CONFIGURE" />
    </intent-filter>
</activity>
```

同时，`appwidget-provider` XML 需要增加 `configure` 属性：

```xml
<appwidget-provider
    ...
    android:configure="com.example.thingsusaid.widget.config.WidgetConfigActivity" />
```

## 6. 数据刷新策略优化

### 6.1 从"全量刷新"到"按需刷新"

阶段 2 中，任何数据变更都会刷新**所有**小组件实例。阶段 3 中，当某个分组的便签发生变化时，理论上只需刷新绑定了该分组的小组件。

### 6.2 精确刷新实现

```kotlin
object TodoWidgetUpdater {
    suspend fun updateForCategory(context: Context, categoryId: Long) {
        withContext(Dispatchers.IO) {
            val manager = GlanceAppWidgetManager(context)
            val dao = AppDatabase.getInstance(context).appDao()
            
            manager.getGlanceIds(TodoGlanceWidget::class.java).forEach { glanceId ->
                val appWidgetId = (glanceId as? AppWidgetGlanceId)?.appWidgetId ?: return@forEach
                val config = dao.getWidgetConfig(appWidgetId)
                if (config?.boundCategoryId == categoryId) {
                    TodoGlanceWidget().update(context, glanceId)
                }
            }
        }
    }
    
    // 保留全量刷新入口（如分组增删等全局变化）
    suspend fun updateAll(context: Context) { ... }
}
```

### 6.3 Repository 刷新调用调整

- **便签/Todo 增删改** → 调用 `TodoWidgetUpdater.updateForCategory(context, categoryId)`
- **分组增删** → 调用 `TodoWidgetUpdater.updateAll(context)`

## 7. 验收标准（Checklist）

- [ ] 从桌面添加小组件时，自动弹出分组选择页面。
- [ ] 选择「生活」分组后，桌面上该小组件显示「生活」分组的便签/Todo 列表。
- [ ] 再添加第二个小组件，选择「工作」分组，两个小组件同时存在于桌面且显示不同内容。
- [ ] 在 App 内修改「生活」分组下的便签，只有绑定「生活」的小组件刷新，绑定「工作」的不受影响。
- [ ] 从桌面移除「生活」小组件后，重新添加一个新小组件并再次选择「生活」，能正常显示。
- [ ] 当绑定分组被删除后，对应小组件显示友好的错误提示（而非崩溃或空白）。
