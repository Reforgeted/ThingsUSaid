# 阶段 6：小组件尺寸多样化（详细设计）

## 1. 阶段目标与范围

### 核心目标
支持多种尺寸的桌面小组件，让用户可以根据桌面空间选择不同大小的组件：
- **小尺寸**：1x1 信息卡片（显示分组名称 + 便签数量）
- **中尺寸**：2x2 紧凑列表（显示 3 条便签）
- **大尺寸**：3x3/4x2 完整列表（显示 5 条便签，当前默认尺寸）

### 范围边界
- 所有尺寸共享同一个 `TodoGlanceWidget` 类，通过 `appWidgetId` 绑定分组。
- 配置页选择分组后，系统根据用户拖拽的尺寸自动渲染对应布局。
- 本阶段不涉及小组件内滚动（Glance 滚动列表兼容性差，保持静态截断列表）。

---

## 2. 技术依赖

无新增依赖，复用现有 Glance 框架。

---

## 3. 小组件尺寸定义

### 3.1 XML 元信息定义

在 `res/xml/` 下为每种尺寸创建独立的 `AppWidgetProviderInfo`：

```xml
<!-- todo_widget_info_small.xml -->
<appwidget-provider
    android:minWidth="40dp"
    android:minHeight="40dp"
    android:maxResizeWidth="80dp"
    android:maxResizeHeight="80dp"
    android:targetCellWidth="1"
    android:targetCellHeight="1"
    android:updatePeriodMillis="0"
    android:widgetCategory="home_screen" />

<!-- todo_widget_info_medium.xml -->
<appwidget-provider
    android:minWidth="110dp"
    android:minHeight="110dp"
    android:maxResizeWidth="180dp"
    android:maxResizeHeight="180dp"
    android:targetCellWidth="2"
    android:targetCellHeight="2"
    android:updatePeriodMillis="0"
    android:widgetCategory="home_screen" />

<!-- todo_widget_info_large.xml -->
<appwidget-provider
    android:minWidth="250dp"
    android:minHeight="180dp"
    android:maxResizeWidth="400dp"
    android:maxResizeHeight="300dp"
    android:targetCellWidth="3"
    android:targetCellHeight="3"
    android:updatePeriodMillis="0"
    android:widgetCategory="home_screen" />
```

**注意**：Android 12+ 推荐使用 `targetCellWidth/Height` 而非 `minWidth/Height`。

### 3.2 Manifest 注册

每个尺寸对应一个独立的 `AppWidgetProvider`（Receiver），但共享同一个 `GlanceAppWidget` 实现：

```xml
<receiver android:name=".widget.TodoGlanceWidgetReceiver" android:exported="false">
    <intent-filter><action android:name="android.appwidget.action.APPWIDGET_UPDATE"/></intent-filter>
    <meta-data android:name="android.appwidget.provider" android:resource="@xml/todo_widget_info_large"/>
</receiver>

<!-- 其他尺寸使用不同的 Receiver 类，但内部委托给同一个 GlanceAppWidget -->
```

**方案选择**：
- **方案 A**：多个 Receiver 类，每个绑定不同的 XML。代码重复少，但需要创建空壳 Receiver。
- **方案 B**：单个 Receiver，在 XML 中使用 `configure` 让用户选择尺寸（已废弃，不适用）。

**建议**：方案 A，为每种尺寸创建独立的 Receiver 类（如 `TodoWidgetSmallReceiver`、`TodoWidgetMediumReceiver`），它们都使用同一个 `TodoGlanceWidget` 实例，只是 XML 配置不同。

## 4. 动态布局渲染

### 4.1 尺寸感知

在 `TodoGlanceWidget.provideGlance` 中，通过 `AppWidgetManager` 获取当前 widget 的实际尺寸，决定渲染哪种布局：

```kotlin
override suspend fun provideGlance(context: Context, id: GlanceId) {
    val appWidgetId = GlanceAppWidgetManager(context).getAppWidgetId(id)
    val appWidgetManager = AppWidgetManager.getInstance(context)
    val options = appWidgetManager.getAppWidgetOptions(appWidgetId)
    val minWidth = options.getInt(AppWidgetManager.OPTION_APPWIDGET_MIN_WIDTH)
    val minHeight = options.getInt(AppWidgetManager.OPTION_APPWIDGET_MIN_HEIGHT)
    
    val sizeCategory = when {
        minWidth <= 80 && minHeight <= 80 -> SizeCategory.SMALL
        minWidth <= 180 && minHeight <= 180 -> SizeCategory.MEDIUM
        else -> SizeCategory.LARGE
    }
    
    // ... 查询数据 ...
    
    provideContent {
        when (sizeCategory) {
            SizeCategory.SMALL -> SmallWidgetContent(...)
            SizeCategory.MEDIUM -> MediumWidgetContent(...)
            SizeCategory.LARGE -> LargeWidgetContent(...) // 当前默认布局
        }
    }
}
```

### 4.2 各尺寸布局设计

#### 小尺寸 1x1（SmallWidgetContent）

```
┌─────────┐
│  生活   │  ← 分组名称（居中）
│   12    │  ← 便签数量（大字号）
└─────────┘
```

- 只显示分组名称和便签总数
- 点击打开 App

#### 中尺寸 2x2（MediumWidgetContent）

```
┌──────────────┐
│ 生活         │
├──────────────┤
│ ☐ 买牛奶     │
│ • 读书笔记   │
│ ☐ 还书       │
└──────────────┘
```

- 显示分组名 + 最多 3 条便签
- 支持 Todo 勾选（同大尺寸）

#### 大尺寸 3x3/4x2（LargeWidgetContent）

```
┌──────────────────┐
│ 生活             │
├──────────────────┤
│ ☐ 买牛奶         │
│ • 读书笔记       │
│ ☐ 还书           │
│ • 日程安排       │
│ ☐ 提交报告       │
└──────────────────┘
```

- 当前默认布局，显示最多 5 条便签
- 支持 Todo 勾选

## 5. 刷新策略调整

### 5.1 精确刷新兼容性

阶段 3 的 `TodoWidgetUpdater.updateForCategory` 需要支持所有尺寸的 widget。由于不同尺寸使用不同的 `appWidgetId`，刷新逻辑不变：

```kotlin
// 查询 widget_configs 中绑定了该 categoryId 的所有 appWidgetId
// 向所有对应的 Receiver 发送广播
```

但因为有多个 Receiver 类，需要向所有 Receiver 类发送广播。或者，所有 Receiver 共享同一个 Action，每个 Receiver 只处理自己管辖的 `appWidgetId`。

**简化方案**：继续使用一个统一的 `TodoGlanceWidgetReceiver`，在 XML 中不指定 `targetCellWidth/Height`，而是使用 `minWidth/minHeight` + `maxResizeWidth/Height`，让用户在桌面上拖拽调整大小。`provideGlance` 中根据实际尺寸动态选择布局。

这种方式**只需要一个 Receiver 和一个 XML 文件**，最简单。

### 5.2 建议的最终方案

**只保留一个 Receiver**，修改 `todo_widget_info.xml`：

```xml
<appwidget-provider
    android:minWidth="40dp"
    android:minHeight="40dp"
    android:maxResizeWidth="400dp"
    android:maxResizeHeight="300dp"
    android:targetCellWidth="1"
    android:targetCellHeight="1"
    android:resizeMode="horizontal|vertical"
    android:updatePeriodMillis="0"
    android:widgetCategory="home_screen" />
```

关键属性 `resizeMode="horizontal|vertical"` 允许用户拖拽调整 widget 大小。当尺寸变化时，系统发送 `APPWIDGET_UPDATE_OPTIONS` 广播，触发 `provideGlance` 重新执行，根据新的尺寸渲染对应布局。

## 6. 关键实现细节

### 6.1 尺寸阈值定义

| 尺寸类别 | 宽度阈值 (dp) | 高度阈值 (dp) | 显示条数 |
|----------|--------------|--------------|---------|
| SMALL | ≤ 80 | ≤ 80 | 0（只显示计数） |
| MEDIUM | ≤ 180 | ≤ 180 | 3 |
| LARGE | > 180 | > 180 | 5 |

### 6.2 小尺寸组件的点击行为

小尺寸组件只显示分组名和数量，点击后打开 App。不显示便签列表，因此不涉及 Todo 勾选。

### 6.3 配置页无需改动

配置页仍然只选择分组，不选择尺寸。尺寸由用户在桌面上拖拽决定。

---

## 7. 验收标准

| 验收项 | 通过标准 |
|--------|---------|
| 尺寸调整 | 在桌面上可以拖拽小组件改变大小（1x1 → 2x2 → 3x3） |
| 小尺寸显示 | 1x1 尺寸只显示分组名和便签数量 |
| 中尺寸显示 | 2x2 尺寸显示分组名 + 最多 3 条便签 |
| 大尺寸显示 | 3x3 尺寸显示分组名 + 最多 5 条便签（现有行为） |
| 动态切换 | 拖拽调整大小后，内容自动切换到对应布局 |
| 数据一致性 | 所有尺寸共享同一个分组绑定配置 |

## 8. 待决策项（请用户确认）

### 问题 1：最小尺寸
小尺寸组件是否只做 **1x1**（仅显示分组名+数量），还是也支持 **2x1**（横向小条，显示 1-2 条便签）？

**用户决策**：不做小尺寸（1x1）。最小尺寸为 2x2。

### 问题 3：中尺寸（2x2）的显示密度
2x2 空间比较小，显示 3 条便签可能略显拥挤。是否：
- A. 显示 3 条（紧凑）
- B. 显示 2 条（宽松，字号稍大）

**用户决策**：B，显示 2 条。宽松布局，字号可稍大。

### 问题 4：尺寸切换时是否保持绑定关系
用户把一个 3x3 组件拖拽到 1x1，再拖回 3x3，绑定关系和数据是否需要重新选择？

**用户决策**：完全保持。绑定关系只与 `appWidgetId` 有关，与尺寸无关。拖拽只是改变布局，不影响数据。

### 补充需求：小组件样式与设置

用户提出：
1. **圆润样式**：小组件整体采用更圆润的圆角设计（通过 Glance `cornerRadius` 或背景 drawable 实现）。
2. **App 内设置**：在 App 中新增「小组件设置」页面，支持：
   - **背景透明度**：Slider 调节 0% ~ 100%
   - **字体大小**：Slider 调节小/中/大
3. 设置值使用 `SharedPreferences` 持久化，保存时发送广播刷新所有小组件。
